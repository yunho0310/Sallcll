네 개를 같은 기준으로

시안첫 화면 주인공첫 방문자재방문자공모전 데모MVP 공수
A · 작업대 시간표 보드 약함 — 설명이 없음 강함 보통 — 기능은 보이나 서사가 없음 낮음
B · 위시 페인트 위시 그리드 강함 보통 — 보드가 한 단계 뒤 강함 — 차별점이 첫 장면 낮음
C · 학기 브리핑 요약 타일 약함 — 빈 화면 문제 강함 보통 높음
D · 발표용 랜딩 카피 + 스크린샷 강함 약함 — 매번 지나쳐야 함 강함 낮음 (별도 1장)

추천: B를 메인으로, A를 로그인 뒤 기본 화면으로

계획서가 위시 추천을 차별 포인트로 못박은 이상 첫 화면이 올클과 똑같은 시간표 보드면 심사에서 축소판으로 읽힙니다. 반대로 매번 위시부터 지나가게 하면 재방문자가 번거로워집니다. 둘을 상태로 나누면 화면 하나만 더 만들면 됩니다.

  1. 비로그인 / 담은 과목 0 → 시안 B. 위시 그리드가 히어로.
  2. 담은 과목 1개 이상 → 시안 A. 보드가 히어로, 위시는 오른쪽 패널의 한 탭.
  3. 시안 C는 Phase 2에서 여석·핀 알림이 들어올 때 꺼냅니다. 지금 만들면 채울 내용이 없습니다.
  4. 시안 D는 11월 발표 주에 정적 1장으로. 지금 만들 필요 없습니다.

킥오프에서 닫혀야 시안이 확정됩니다

  1. 제품명 — 지금은 워드마크 자리만 비워 뒀습니다. 로고가 들어가면 상단 바 높이가 바뀝니다.
  2. 교시 체계 — 그리드 행 개수가 여기서 나옵니다. 1–7교시로 그렸지만 학사 교시표를 따라야 합니다.
  3. 위시 매칭 A/B — 정책 A로 가면 시안 B의 추천 개수가 확 줄어서, 리스트보다 “조건 완화” 안내가 더 중요해집니다.
  4. 프론트 스택 — 이 그리드는 CSS Grid 한 덩어리라 Next.js면 그대로 옮겨집니다. Flutter Web이면 다시 그려야 합니다.
